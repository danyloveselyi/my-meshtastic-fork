## 🔴 Проблема #2: ОЧЕНЬ МЕДЛЕННАЯ запись при активном BLE (КРИТИЧНО!)

### Симптомы из последних логов:
```
WARN | 12:41:32 144 Flash write event not received for address 0x00086000, but data appears written
WARN | 12:41:42 154 Flash write event not received for address 0x00086004, but data appears written
WARN | 12:41:52 164 Flash write event not received for address 0x00086008, but data appears written
...
DEBUG | 12:44:03 295 lfs_prog: Progress: 16/1024 words written (1.6%)
```

### Проблема:
- **Каждое слово пишется ~10 секунд!** (12:41:32 → 12:41:42 → 12:41:52...)
- Для записи 1024 слов потребуется **~170 минут (2.8 часа)!**
- Это происходит потому что код ждет **полный таймаут 10000ms** перед проверкой flash

### Причина:
В текущей реализации проверка flash происходит **ПОСЛЕ** таймаута:
```cpp
if (!success) {
    // Ждем 10 секунд...
    if ((millis() - start_time) >= 200) {  // Проверка только ПОСЛЕ таймаута!
        // Проверяем flash
    }
}
```

### Решение:
Проверять flash **РАНЬШЕ** - если прошло 200ms, сразу проверяем flash и продолжаем:
1. Уменьшить таймаут polling до 500ms (достаточно для получения события)
2. Если событие не получено за 500ms, проверяем flash напрямую
3. Если данные записаны, продолжаем без ожидания полного таймаута

### Файлы для изменения:
- `variants/rak4631_lite/NodeDB-extended-fs.cpp` - функция `lfs_prog()`
