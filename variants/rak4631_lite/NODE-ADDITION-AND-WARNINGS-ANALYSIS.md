## WARN "No suitable channel found for decoding, hash was 0x0!"

### Причина:

Это происходит когда пакет приходит с `channel hash = 0x0`, и ни один канал не может его декодировать.

**Возможные причины:**

1. **Пакет от ноды с другим каналом/PSK:**
   - Нода использует другой канал или PSK
   - Ваша нода не знает этот канал
   - Это нормально в mesh сети с разными каналами

2. **Пакет поврежден:**
   - Пакет был поврежден при передаче
   - Hash не может быть декодирован

3. **Нода еще не настроена:**
   - Нода только что появилась в сети
   - Еще не обменялась ключами/каналами

### Когда это происходит:

Из лога видно:
```
INFO | 15:27:24 55 [Router] Received routing from=0x77327c4e, id=0x9f341dd2, portnum=24, payloadlen=49394
WARN | 15:27:24 55 [Router] No suitable channel found for decoding, hash was 0x0!
```

Это происходит **ДО** добавления ноды в базу, когда:
- Пакет приходит от неизвестной ноды
- Нода еще не обменялась ключами
- Канал не настроен

**Это НОРМАЛЬНО** для mesh сети! ✅

### Из лога видно последовательность:

```
1. INFO | 15:27:33 64 [Router] Received nodeinfo from=0x474bccd6
   → Получен пакет с информацией о ноде

2. INFO | 15:27:33 64 [Router] Adding node to database with 128 nodes
   → Нода добавлена в базу (в RAM)
   → **НОДА УЖЕ ДОСТУПНА ДЛЯ ОБМЕНА СООБЩЕНИЯМИ!** ✅

3. INFO | 15:27:33 64 [Router] Update Node Pubkey!
   → Обновлен публичный ключ ноды

4. INFO | 15:27:33 64 [Router] Saving NodeDB: 128 nodes, 9774 bytes encoded
   → Начато сохранение в файл (асинхронно)

5. WARN | 15:27:33 64 [Router] Page 134 erase event not received...
   → Стирание страниц (асинхронно, не блокирует)

6. INFO | 15:27:35 66 [Router] Saved /prefs/nodes.proto successfully
   → Сохранение завершено

7. INFO | 15:27:35 66 [Router] Received routing from=0x474bccd6
   → Пакет от новой ноды (нода уже доступна!)
```

### Критический момент:

**Нода становится доступной для обмена сообщениями СРАЗУ после добавления в базу (шаг 2), НЕ после сохранения на диск!**

**Почему это важно:**
- Сохранение на диск происходит **асинхронно** (не блокирует)
- Нода доступна для обмена сообщениями **до** завершения сохранения
- Это позволяет быстро обмениваться сообщениями даже во время записи

### Почему стирается 6 страниц для файла 10KB?

Это нормально для LittleFS:
- LittleFS использует wear leveling (равномерный износ)
- Может стирать страницы, которые не используются
- Это обеспечивает долговечность flash памяти
- Размер файла не всегда равен количеству стертых страниц
