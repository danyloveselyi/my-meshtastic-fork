# Анализ падения на 80 страницах

## Проблема
Устройство "умирало" (USB не виден, зеленый LED не горит) при попытке использовать 80 страниц (320 KB) для filesystem.

## Из логов видно:

### 1. Standard конфигурация (7 страниц, 28 KB):
- **Start**: 0x000ED000 (page 237)
- **End**: 0x000F3FFF (page 243, inclusive)
- **Gap to bootloader**: 0 bytes (CRITICAL!)
- **Status**: Работает, но опасно (0 байт зазора)

### 2. Extended конфигурация (80 страниц, 320 KB):
- **Start**: 0x00080000 (page 128)
- **End**: 0x000CFFFF (page 207, inclusive)
- **Gap to bootloader**: 144 KB (36 pages) - SAFE!
- **Status**: Теоретически безопасно

## Почему падало на 80 страницах?

### Возможные причины:

#### 1. **Несоответствие между linker script и framework**
- Linker script ограничивает application до 0x80000
- Custom framework должен использовать LFS_FLASH_ADDR = 0x80000
- Если custom framework НЕ обновлен, он может пытаться использовать стандартный адрес (0xED000)
- Результат: framework пытается монтировать 80 страниц по неправильному адресу

#### 2. **Двойное монтирование filesystem**
- `preFSBegin()` может вызывать `InternalFS.begin()` или `format()`
- Затем `fsInit()` снова вызывает `FSBegin()` -> `InternalFS.begin()`
- Результат: попытка монтировать уже смонтированную filesystem = corruption

#### 3. **Неправильная последовательность инициализации**
- USB должен быть инициализирован ПЕРЕД длительными операциями (erase pages)
- Если `preFSBegin()` выполняет длительное erase ПЕРЕД USB init, USB не стартует
- Результат: устройство "мертво" (USB не виден)

#### 4. **Проблема с SoftDevice API**
- `sd_app_evt_wait()` может зависать, если SoftDevice не полностью инициализирован
- Если это происходит в `preFSBegin()` (до полной инициализации), система зависает
- Результат: устройство не отвечает

#### 5. **Bootloader overlap (маловероятно, но возможно)**
- Если linker script НЕ применен правильно
- Application может попытаться использовать адреса после 0x80000
- Результат: конфликт с filesystem

## Решение:

### Для работы 80 страниц нужно:
1. ✅ Custom framework с `LFS_FLASH_ADDR = 0x80000`, `LFS_FLASH_TOTAL_SIZE = 80 * 4096`
2. ✅ Linker script ограничивающий application до `0x80000`
3. ✅ Правильная последовательность: USB init -> Filesystem init (не наоборот!)
4. ✅ Избегать `sd_app_evt_wait()` в `preFSBegin()` - использовать `delay()` с timeout
5. ✅ Убедиться, что нет двойного монтирования filesystem

## Текущий статус:
- ✅ Standard конфигурация (7 страниц) - работает
- ⚠️ Extended конфигурация (80 страниц) - отключена из-за падений
- ✅ Детальное логирование добавлено для диагностики

## Следующие шаги для включения 80 страниц:
1. Обновить custom framework с правильными константами
2. Убедиться, что linker script применен
3. Проверить последовательность инициализации (USB перед filesystem)
4. Заменить `sd_app_evt_wait()` на `delay()` в `preFSBegin()`
5. Избежать двойного монтирования filesystem
