# Анализ увеличения количества узлов для RAK4631 Lite

## 1. Краткое резюме
- **Цель:** увеличить число узлов, удерживаемых в памяти устройства, без деградации стабильности.
- **Текущее ограничение:** compile-time `MAX_NUM_NODES = 256` в `variants/rak4631_lite/variant.h` (≈50–60 КБ статически заняты в RAM).
- **Основные потребители памяти:** `NodeDB` (структуры `meshtastic_NodeInfoLite`) и `PacketHistory` (дедупликация пакетов).
- **Динамический лимит `dynamic_max_nodes`:** влияет только на команды DeviceStats, но не меняет реальные ограничения `NodeDB`.

## 2. Где хранится информация об узлах
| Компонент | Файл | Назначение |
|-----------|------|------------|
| `NodeDB` | `src/mesh/NodeDB.cpp` | Основная база узлов. Вектор `nodeDatabase.nodes` расширяется до `MAX_NUM_NODES` при инициализации. |
| `DynamicNodes` | `src/mesh/DynamicNodes.cpp` | Определяет `DEFAULT_MAX_NODES` и `dynamic_max_nodes` (weak-связи, могут переопределяться вариациями). |
| `DeviceStatsModule` | `src/modules/DeviceStatsModule.cpp` | Команды `/maxnodes`, `/setmaxnodes`, мониторинг памяти, но фактически не меняют compile-time лимит. |
| `PacketHistory` | `src/mesh/PacketHistory.cpp` | Хранит историю пакетов, резервируя `MAX_NUM_NODES` записей (ещё ~4–5 КБ). |

## 3. Расход памяти
- `sizeof(meshtastic_NodeInfoLite)` ≤ 200 байт (assert в `mesh-pb-constants.h`). Практический размер ~166–180 байт.
- При `MAX_NUM_NODES = 256` статически резервируется `256 × ~180 ≈ 46 КБ` под узлы + накладные расходы вектора → ~55–60 КБ RAM.
- `PacketHistory::recentPackets.reserve(MAX_NUM_NODES)` ≈ ещё 4–5 КБ.
- Минимальный свободный heap контролируется `MINIMUM_SAFE_FREE_HEAP = 8192` (8 КБ): при меньшем значении `NodeDB::isFull()` перестаёт добавлять новые записи.

## 4. Выявленные узкие места
1. **Жёсткая зависимость от `MAX_NUM_NODES`:** все критичные проверки (`NodeDB::isFull`, сериализация, PacketHistory) используют compile-time значение. Даже если `dynamic_max_nodes` повышен, новые узлы не сохраняются.
2. **Eager allocation:** массив `nodeDatabase.nodes` инициализируется полным размером при старте, что тратит RAM даже при малом числе узлов.
3. **Файловый формат (`nodes.proto`):** размер файла рассчитывается из `MAX_NUM_NODES`, что усложняет динамическое увеличение лимита без пересборки.
4. **Стратегия вытеснения:** при переполнении `NodeDB` удаляет «самый старый скучный» узел, что может приводить к потере важных маршрутизаторов, если лимит невысок.

## 5. Простое решение (минимальные правки)
1. **Увеличить `MAX_NUM_NODES`** в `variants/rak4631_lite/variant.h` (например, до 320–384). Это сразу расширит NodeDB и PacketHistory.
2. **Обновить ограничения в DeviceStats** (`/maxnodes`, `/setmaxnodes`) и тексты подсказок, чтобы пользователь видел новые границы.
3. **Мониторить свободную память:** в `DeviceStatsModule::formatDetailedMemoryStats` показывать предупреждение, если `memGet.getFreeHeap() < 24 КБ`, чтобы пользователь не наращивал узлы вслепую.
4. **Smoke-тест:** сборка `pio run -e rak4631_lite`, отправка `/setmaxnodes <новый лимит>,123456`, наблюдение за `/mem` и `/nodes` при имитации нагрузки.

*Ожидаемый эффект:* +30–50% узлов без изменения архитектуры. Ограничение всё ещё RAM (для nRF52840 реально ≈350 узлов при стабильной работе).

## 6. Расширенное решение (максимизация)
### 6.1 Ленивая аллокация
- В `NodeDB::installDefaultNodeDatabase()` убрать `std::vector<...>(MAX_NUM_NODES)` и заменить на `reserve(dynamic_max_nodes); resize(numMeshNodes)`.
- `meshNodes->resize(MAX_NUM_NODES);` в `loadFromDisk()` заменить на `meshNodes->resize(std::min((size_t)dynamic_max_nodes, meshNodes->size()));`.
- В `NodeDB::isFull()` проверять `numMeshNodes >= dynamic_max_nodes` + свободную память.

### 6.2 Сегментация данных
- Разделить `meshtastic_NodeInfoLite` на «горячую» (ID, `last_heard`, RSSI) и «холодную» часть (User, Position). Холодную часть можно хранить во вторичном векторе или в flash.
- При необходимости ответа (`/nodes`, UI) загружать полные данные.

### 6.3 Внешнее хранение
- Создать файл `nodes.slab` и сериализовать туда узлы, не активные > N часов. В RAM держать только последние ~200.
- При приёме пакета/команды проверять кеш; при необходимости подгружать из flash и освежать таймстамп.

### 6.4 Усовершенствовать вытеснение
- Сохранять роутеры, избранных и проверенных пользователей в «pin-списке», вытеснять только «boring» узлы с давним `last_heard`.
- Добавить квоты: например, минимум 50 мест под роутеры, остальные под клиентов.

### 6.5 PacketHistory
- Перевести `recentPackets` на кольцевой буфер фиксированного размера (например, 128 записей) + очистку по времени. Экономия нескольких КБ под будущий рост NodeDB.

*Ожидаемый эффект:* возможность хранить 500+ узлов, ограничение сместится из RAM во flash/файловую систему. Потребуются дополнительные тесты сериализации и восстановления.

## 7. Пути реализации

### 7.1 Базовый путь
1. Изменить `MAX_NUM_NODES` и пересобрать прошивку.
2. Скорректировать команды DeviceStats.
3. Прогнать `platformio run -e rak4631_lite` + `platformio device monitor` с виртуальной нагрузкой.

### 7.2 Расширенный путь
1. Рефакторинг инициализации `NodeDB` (lazy allocation) + переход на `dynamic_max_nodes` во всех проверках.
2. Обновление сериализации (`getMaxNodesAllocatedSize`, `meshNodes->resize`) и миграция файлового формата, чтобы поддерживать разные размеры без factory reset.
3. Реализация модулей «холодного хранения» (flash, отдельный файл) и адаптация DeviceStats для отчёта по двум слоям данных.
4. Добавление юнит/интеграционных тестов: эмуляция заполнения базы до нового лимита, проверка дуального хранения, восстановление после перезагрузки.
